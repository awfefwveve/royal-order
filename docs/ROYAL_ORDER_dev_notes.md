# 황실 칼전 — 개발 패키지 (1단계 벤치마크 + 2단계 게임플레이 코어)

게임 전체 설계가 "한 판에 몬스터를 몇 마리까지 돌릴 수 있나"에 달려 있어서, 이 숫자부터 측정합니다.
네트워크(Fusion)는 아직 붙이지 않았습니다. 몬스터 로직은 Fusion과 완전히 분리된 `KnifeWar.Core`에 있어서, 2단계에서 그대로 서버에 올립니다.

## 들어있는 것

| 폴더 | 내용 |
| --- | --- |
| `Assets/KnifeWar/Core` | 몬스터 시뮬레이션 (정수 mm 레인 좌표, Jobs + Burst, 공간 분할, 랙 보정 기록, 몬스터 칼 판정, 트래픽 추정) |
| `Assets/KnifeWar/Bench` | 벤치마크 러너 — 서버 CPU 측정 / 클라 렌더링 측정 |
| `Assets/KnifeWar/Editor` | 상단 메뉴 `KnifeWar` — 씬 자동 생성, 헤드리스 서버 빌드 |
| `Assets/KnifeWar/Core/PlayerHitboxes.cs` | 부위별 캡슐 히트박스, 플레이어 위치 기록(보간 되감기), 칼 판정 (두꺼운 스윕으로 대상 → 얇은 조준선으로 부위) |
| `Assets/KnifeWar/Core/KnifeCombat.cs` | 서버 권위 칼 전투: 좌클 베기·우클 찌르기, 윈드업·회복, 랙 보정, 백스탭, 부위 배율 |
| `Assets/KnifeWar/Core/RoundRules.cs` | 라운드 진행: 준비 단계 직업 선택(인원 제한 없음), 부활 없음, 승리 판정(임시) |

| `CoreTests~` | 유니티 밖에서 돌리는 테스트 (유니티는 이 폴더를 무시) |

## 설치 (10분)

1. Unity Hub에서 **Unity 6 LTS**로 새 프로젝트 생성 — 템플릿은 **Universal 3D (URP)**
2. Unity Hub → 설치된 에디터 → 모듈 추가에서 **Windows Dedicated Server** 설치 (Linux 서버 측정까지 하려면 **Linux Dedicated Server**도)
3. 이 zip의 `Assets/KnifeWar` 폴더를 새 프로젝트의 `Assets` 안에 복사
4. `Window → Package Manager → Unity Registry`에서 **Collections** 설치 (Burst, Mathematics가 같이 설치됨)
5. 프로젝트 루트에 `.gitignore`, `.gitattributes`도 복사 (GitHub + Git LFS용)

## 실행

### 에디터에서 빠르게 확인
1. 상단 메뉴 `KnifeWar → 1. 몬스터 벤치 씬 만들기`
2. Hierarchy의 `BenchRunner`에서 **Mode** 선택 (`ServerSim` / `ClientRender`) 후 Play
3. 화면 왼쪽 위에 단계별 결과가 표시되고, 끝나면 CSV가 저장됩니다 (`KnifeWar → 결과 폴더 열기`)

에디터 수치는 실제보다 나쁘게 나옵니다. **확정 숫자는 아래 빌드로 측정**하세요.

### 정식 측정 (빌드)

**서버** — `KnifeWar → 2. 서버 벤치 빌드 (Windows 헤드리스)` 후, 빌드 폴더에서:
```
ServerBench.exe -batchmode -nographics -kwMode server -tickRate 128 -workers 0 -budget 40
```
- `-workers 0` = 메인 스레드만 사용 → vCPU 1개 서버와 비슷한 조건
- `-budget 40` = 128틱 한 틱(7.8ms) 중 40%(3.1ms)를 몬스터에 할당. 나머지는 플레이어 판정·넷코드 몫
- 64틱 비교: `-tickRate 64`로 한 번 더

**클라** — `KnifeWar → 4. 클라 렌더 벤치 빌드 (Windows)` 후 `ClientBench.exe` 실행.
목표 최소 사양에 가까운 PC에서 돌린 값이 기준입니다.

### 결과 읽는 법
- 서버 CSV: `avg_ms`, `p99_ms`(상위 1% 느린 틱), `kb_per_sec_per_client`(클라 1명당 트래픽 추정), `pass`
- 클라 CSV: `avg_fps`, `low1_fps`(1% 최저), `pass`
- **몬스터 상한 = 서버 최대치와 클라 최대치 중 작은 값.** 이 숫자를 모든 서버에 고정합니다.

## 지금 단계의 한계 (알고 있는 것)
- 몬스터 외형은 캡슐이고 애니메이션은 위아래 흔들림으로 흉내만 냅니다. VAT(버텍스 애니메이션 텍스처) 적용은 다음 작업이라, 실제 클라 최대치는 이보다 조금 낮아질 수 있습니다.
- 클라 벤치는 서버 전체 시뮬레이션을 같이 돌립니다. 실제 클라는 이동만 계산하므로 실제보다 보수적인(낮은) 값이 나옵니다.
- 트래픽은 이벤트 크기 추정값입니다. 실제 넷코드를 붙이면 다시 측정합니다.

## 2단계 게임플레이 코어 (넷코드 독립)
플레이어 판정을 Fusion 히트박스 대신 직접 구현했습니다. 판정 규칙을 우리가 100% 쥐고, 나중에 넷코드를 바꿔도 그대로 씁니다. Fusion은 입력 전달과 상태 동기화만 맡깁니다.

- **되감기**: 클라가 보던 "틱 + 보간 비율"로 상대를 되감고, 윈드업 동안 클라 화면이 진행한 만큼도 반영. 최대 250ms (넘으면 한도로 잘림 → 핵 방지)
- **부위 판정**: 칼 체감은 관대하게(두께 0.3m 스윕), 부위는 정확하게(조준선). 정면 머리 80, 몸통 50, 등 뒤 찌르기 즉사
- **수치**: `KnifeTuning`에 모아 둠. 블스 체감은 플레이테스트로 맞춥니다
- **임시값**: 승리 조건(전멸, 시간 초과 시 생존자 수), 7선승, 라운드 120초, 마나·코스트 — 기획 확정되면 교체

## 검증한 것
유니티 밖 테스트로 확인했습니다 (`CoreTests~`).
- 몬스터: 60초 전투에서 슬롯 누수 없음, 같은 입력이면 결과 완전히 동일(결정적), 몬스터 칼 판정 적중·빗나감, 랙 보정 기록
- 칼 판정 14개: 머리/몸통 구분, 사거리·각도 빗나감, **랙 보정 켜면 맞고 끄면 빗나가는 것까지 확인**, 되감기 한도, 백스탭 즉사, 회복 시간 연타 무시, 아군 판정 없음, 앉은 상대 머리 위 빗나감
- 라운드 9개, 마법사 6개: 직업 선택·고정·유지, 전멸·시간 초과 승리, 이탈자 처리, 마나 회복, 코스트, 팀 상한 공유, 버프 지속
유니티 에디터 안에서는 아직 컴파일해보지 못했으니, 에러가 나면 콘솔 내용을 그대로 보내주세요.
